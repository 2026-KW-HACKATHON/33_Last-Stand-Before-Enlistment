DB가 없는 `local` 프로필의 테스트 성공은 Migration 또는 Supabase 연결 성공이 아니다. 기존 #1 문서의 과거 결과를 이번 실행 결과로 복사하지 않는다.

## 2. 공통 사전 조건

1. 운영과 분리된 테스트 PostgreSQL 및 버전·적용 역할·Migration 이력을 확인한다. 실제 접속정보는 보고서에 남기지 않는다.
2. 지역 4개 이상, 회원 2명 이상, 기관 2개, 각 유형 게시물·투표 2개 이상을 합성한다. 잘못된 귀속을 시험할 때 참조 ID 자체는 존재해야 한다.
3. DB 제약의 실패는 독립 트랜잭션 또는 savepoint로 격리한다. 실패 뒤 중단된 트랜잭션을 그대로 계속 사용하지 않는다.
4. 서비스 시험은 BEFORE/AFTER 행 수·현재 관계·이벤트 수·최초 시각을 함께 비교한다. 권한은 FE 버튼이 아니라 실제 서버 결과로 확인한다.
5. 동시성 시험은 독립 연결 2개 이상을 준비하고 시작 지점/장벽을 맞춘다. 순차 요청 두 번을 동시성 통과로 기록하지 않는다.

## 5. Migration 적용·재실행 시험 — #3

| ID | 절차 | 통과 기준 |
| --- | --- | --- |
| MG01 | 빈 격리 테스트 DB에 최초 적용 | 오류 없음, 카탈로그와 ERD/준비 명세 일치. 실제 PostgreSQL 버전 기록 |

| MG04 | 적용 중 의도적 오류 후 수정된 후속 절차로 재시도 | 도구의 실패/트랜잭션 이력 확인, 부분 적용·이력 불일치 없이 복구 |

| MG06 | 합의된 백업·복구 방법으로 테스트 데이터 복구 | 운영 삭제 없이 격리 DB에서 데이터/Schema/이력 정합성 복구. destructive down Migration 자동 실행 금지 |
| MG07 | 분리된 시연 seed를 재실행 | 중복 정본·중복 자격·의도치 않은 관계 덮어쓰기 없음. identity 후속 발급 충돌 없음 |
| MG08 | 배포 적용 역할·일반 앱 역할의 접근 범위 확인 | 합의된 권한만 가능. 브라우저/공유 게스트가 내부 DB·증빙·담당자 정보에 직접 접근하지 못함 |

도구가 아직 정해지지 않아 명령·이력 테이블명을 추측해 작성하지 않았다. 도구와 실행 경로가 합의되면 정확한 적용/재실행/실패 복구 명령을 추가한다.
