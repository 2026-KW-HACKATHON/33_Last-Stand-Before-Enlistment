## MVP 범위·구현 상태 재정렬 (2026-10-07)

이번 재검토는 기존 NON-MVP 표에서 서버 개발 상태가 화면 제외로 전파된 부분을 바로잡는다. 이 절과 수정된 범위 표는 같은 주제의 10/6 제외 분류를 대체한다. 기능 ID·지역 권한·소유권 정책은 유지한다. 10/7에 명시적으로 제품에서 제거·대체한 흐름은 아래 예외로 구분한다.

- **MVP 포함**은 이번 서비스가 제공할 사용자 경험·화면·기능을 뜻한다. Backend 개발 완료와 같은 의미가 아니다. `MVP 포함 + BE API 미구현`은 유효한 상태다.
- **Figma 최종디자인 존재 → FE 구현 대상.** Backend API 없음 → BE API 미구현이다. 서버 계약 미확정·개발 지연이나 현재 Frontend 화면 부재만으로 제품 범위를 제거하지 않는다.
- MVP Frontend 범위와 Backend 구현 상태는 별도로 관리한다. 최신 `front/develop`과 `back/develop`은 각각 현재 구현 상태를 확인하는 기준이며 최종 화면의 정답이나 제품 범위의 상한이 아니다.
- Backend가 준비되지 않은 화면은 합의된 Contract와 Mock 데이터로 사용자 흐름을 먼저 구현할 수 있다. 계약이 없는 부분은 계약 확인 필요로 남기고 화면 검증용 Mock의 가정을 실제 서버 계약으로 확정하지 않는다.
- Mock 구현은 실 API Integration 완료가 아니다. Backend 준비 후 Mock/Data Adapter를 실제 API Adapter로 교체하고 권한·오류·저장/조회 일관성을 검증해 Integration을 완료한다.
- Figma에 존재하는 입력·버튼·메뉴·상태는 관련 기능의 FE 범위다. 실제 전송·예약·푸시·서버 저장은 별도의 Backend 상태와 완료 조건을 가진다. Mock 성공을 실제 접수·저장·발송으로 안내하지 않는다.
- **명시적인 제품 제거 예외:** Privy로 대체된 자체 비밀번호 설정/로그인/변경/찾기/재설정과 자체 가입 코드 발급, 이웃·기관 증빙 입력/첨부/신청/제출/접수·실제 심사 흐름은 10/7 확정 결정대로 제외한다. 계정 이메일 변경·탈퇴 화면은 이번 추가 결정으로 복구하고 본인 확인은 Privy를 사용한다. Figma의 현재 비밀번호 입력/검증은 Privy 확인·실패/취소 UI로 대체한다. 실제 Privy 지원 흐름·로컬 회원 갱신/탈퇴 계약은 확인 필요다. 단순 API 부재와 구분하며 Figma 잔존 화면은 아래 전수 대조에서 예외로 기록한다.

## 확정 정책 보완 (2026-10-04)

이 절은 본 문서의 기존 문장과 미정 질문 중 아래 항목과 충돌하는 내용을 대체한다.

- 게시물의 `공감해요`, `필요해요`, `궁금해요`는 각각 반응 유형이며, 일반 명칭은 `반응`이다. 게시물 `반응 수`는 공감해요 수 + 필요해요 수 + 궁금해요 수이다. `공감해요` 버튼 이름은 유지한다.
- 해당 게시물 지역의 이웃 인증을 완료한 로그인 회원은 댓글과 답글에 `좋아요`와 `싫어요`를 남길 수 있다. 공유 링크 게스트는 댓글·답글 작성만 가능하고 좋아요·싫어요 평가는 할 수 없다. 두 평가는 상호배타적이고, 반대 버튼을 누르면 기존 평가를 바꾸며 현재 선택 버튼을 다시 누르면 취소한다. 댓글 정렬은 `좋아요순`(부모 댓글 좋아요 수 내림차순, 동률이면 최신 작성 우선)과 `최신순`이며 답글은 부모 댓글 아래에 두며 답글의 좋아요 수를 부모 댓글 정렬 기준에 합산하지 않는다.
- 회원이 댓글 또는 답글에 좋아요나 싫어요를 남기면 해당 게시물은 `참여한 게시물`에 포함한다. 게시물 반응, 댓글·답글 작성, 댓글·답글 평가, 투표 참여도 같은 목록에 기록한다.
- 게시물 유형은 `지역 안건`, `지역 활동 정보`, `투표`로 통일한다. 투표는 독립 게시물이다. 게시 완료 후 게시한 게시물의 상세로 이동한다.
- 게스트는 공유받은 특정 게시물 상세 컨텍스트 안에서만 이용하며 일반 메인·통합 게시판·전체 지도 탐색은 제공하지 않는다. `게스트` 이름으로 댓글과 답글을 작성할 수 있고 답글은 원 부모 댓글 아래 1단계만 저장한다. 기존 답글에 답하면 동일 부모 아래에 저장하고 대상 사용자명을 표시한다.
- 기관 인증 사용자는 익명 게시물을 작성할 수 없다. 기관 담당자는 전체 안건을 열람하고 게시물 반응 수 내림차순으로 확인할 수 있으며, 자신에게 인증된 담당 지역의 지역 안건만 채택해 기관 ↔ 지역 안건 관계/기록을 생성한다. 채택은 게시물 상태 변경이 아니다. 반응 수는 위 합계 정의를 따른다.
- 지역 참여 기능(게시, 댓글·답글, 게시물 반응, 댓글·답글 평가, 투표)은 해당 지역 이웃 인증을 완료한 회원만 사용할 수 있다. 게스트 공유 링크 댓글·답글은 예외다. 다른 지역은 열람 전용이다.
- 탐색 지역을 바꾸면 현재 탐색 지역만 임시 변경하며 기본 활동 지역은 유지한다. 관심 지역 개수 제한 없음·0개 허용은 FE 관심 지역 화면에도 적용한다.
- 투표는 선택지를 고른 뒤 `투표 제출` 버튼을 눌러 제출한다. 기존 선택이 있는 상태에서 다른 선택을 제출하면 `선택을 변경하시겠습니까?` 확인을 거친다. 확인 시 기존 표를 대체하고 취소 시 기존 표를 유지한다.
- 이용약관 동의와 개인정보 수집·이용 동의는 필수이고 소식·이벤트/마케팅 수신 동의는 선택이다. 필수 동의가 없으면 회원가입을 완료할 수 없다. 이웃 인증은 해당 지역 거주민의 지역 참여 자격 확인 절차다. 증빙 선택·첨부·신청 제출·접수·실제 인증 처리는 이번 MVP에서 제외한다. 별도 시연용 계정의 완료 지역을 서버에 준비하고 상태 조회·최대 3지역·해당 지역 참여 자격은 유지한다. 일반 가입·Privy 로그인·활동 지역 설정·기관 자격만으로 이웃 자격을 부여하지 않는다. 계정 준비는 #75, 조회 계약은 #74/#11을 따른다. 최종 제품의 운영자 정성 평가·제출 후 1주일 이내 응답·승인 완료 조건은 비-MVP 심사 정책으로 유지한다. 한 사용자는 최대 3개 지역까지 이웃 인증을 완료할 수 있다. 구체적으로 인정할 거주 증빙 종류와 운영 데이터 구조 세부는 후순위로 두되 MVP 상태·완료 지역 관계 저장은 포함한다.

## 한 줄 정의

지역 주민에게 지역 문제 참여와 해결의 기회를 제공하여 주민이 지역 변화에서의 주도권을 가지게 한다.

## 제품 목표

주민이 지역 문제에 대한 정보가 없거나 참여할 시간이 없어서 지역 문제에 잘 참여하지 않는다. 이러한 상황에서 주민들이 쉽게 참여하도록 만든다.

## 추진 배경

주민의 참여가 충분히 이루어지지 않으면 지역의 다양한 의견이 정책과 지역 변화 과정에 반영되지 못하고, 일부 의견에 편중되거나 추후 주민 간·행정과 주민 간 갈등으로 이어질 수 있다.

## 사용자 문제

사용자, 즉 주민은 참여 창구에 대한 정보를 별로 가지고 있지 않으며, 참여할 시간 또한 부족하다. 결국 주민의 다양한 의견이 정책과 지역 변화 과정에 반영되지 못하고, 일부 의견에 편중되거나 추후 주민 간·행정과 주민 간 갈등으로 이어질 수 있다.

## 해결 방안

[사용자 유형과 권한]

MVP 주요 사용자는 주민 회원, 공유 링크 게스트, 기관 인증 사용자(민원담당자)다. 기존 회원 역할은 지역 문제 참여자와 기관 인증 사용자로 유지하고 거주자·학생·직장인·상인은 복수 선택 가능한 프로필 속성으로 유지한다. Privy 이메일 OTP로 인증·로그인한다. 최초 사용자는 필수/선택 동의·프로필·활동 지역을 완료해 로컬 회원으로 가입한다. 자체 비밀번호 설정·확인·로그인과 자체 가입 코드 발급은 대체한다. OTP 세부 제한과 토큰/회원 연결 계약은 #74에서 합의한다. `returnTo`를 전체 과정에서 보존하고 복귀만으로 참여·북마크를 자동 실행하지 않는다. 이용약관·개인정보 수집·이용은 필수, 마케팅/소식 수신은 선택이며 필수 동의 없이 완료할 수 없다. 인증 재발송·불일치·만료·발송 실패 처리도 MVP다. 로그인 실패는 `로그인에 실패했습니다`로 안내하고 이메일 존재 여부 등 구체 원인을 구분하지 않는다.

게스트는 공유 링크로 받은 특정 게시물 상세에서만 공개 본문·사진·댓글/답글·반응 수·투표 결과를 열람하고 `게스트` 이름으로 댓글/답글을 작성한다. 일반 메인·통합 게시판·전체 지도는 탐색하지 않는다. 게시물 반응·댓글 평가·투표·북마크 시도 시 `로그인이 필요한 기능입니다.` 안내 후 로그인으로 이동한다. 로그인/가입 과정에서 returnTo를 보존하고 완료 후 원 게시물로 복귀하며 기존 동작을 자동 실행하지 않는다. 일반 진입은 메인으로 이동한다. 게스트의 전화번호 인증·문자 알림과 가입 후 게스트 댓글 자동 이관은 제공하지 않는다.

지역 게시·댓글/답글·반응·댓글 평가·투표는 해당 지역 이웃 인증 완료 회원만 가능하고 공유 링크 게스트 댓글/답글만 예외다. 활동 지역 설정·기관 인증은 이웃 인증을 대체하지 않는다. 다른 지역은 열람 전용이다.

[핵심 기능과 화면]

MVP 시작 화면은 브랜드·슬로건·로그인·회원가입 진입을 제공하고 이미 로그인한 사용자는 시작 화면 → 메인 화면 순서로 이동한다. 메인은 현재 지역 콘텐츠와 통합 게시판·이슈 지도·게시물/투표 상세 진입을 제공한다. 하단의 메인·지도·글쓰기·알림·마이 5개 메뉴와 헤더의 설정·알림을 제공한다. 알림 API가 없어도 알림 화면과 Mock 목록·빈/Loading/Error·읽음/미읽음·상세 이동은 FE 구현 대상이다. 현재 탐색 지역의 콘텐츠가 없으면 해당 섹션과 게시판 CTA를 유지하며 `아직 등록된 게시물이 없습니다.`를 표시한다.

통합 게시판은 지역 안건·지역 활동 정보·투표 세 유형을 같은 공개 목록에서 조회하고 지역·유형·주제를 필터링한다. 지역 조건 아래 유형을 먼저 선택하고 해당 유형의 주제를 선택한다. ‘전체’는 조회 필터이지 저장값이 아니다. 주제는 교통·주거·안전·복지·생활정보·환경·기타다. 목록은 공개 정보·반응 수·댓글 정보를 표시하고 신규 게시물도 동일 원본 목록에 반영한다. 기본 활동 지역과 임시 탐색 지역을 구분한다.

AI 안건 요약은 MVP다. 공개 지역 안건 원문의 핵심을 자연스러운 3문장 한 문단으로 제공하고 원문에 없는 사실을 추가하지 않는다. 생성 상태를 표시하고 실패하거나 원문이 짧으면 원문을 우선 제공한다. 요약과 원 게시물을 연결하고 원문 열람 경로를 제공한다. 게스트 요약 열람은 공유받은 상세에 한정한다. AI 추천 카드·추천 이유·새 추천·후보 없음과 관심 지역/키워드 관리도 FE 구현 대상이다. 추천 산출·저장 서버는 BE API 미구현 / 계약 확인 필요이며 AI 요약과 독립적으로 연동한다.

[통합 게시물 작성·열람]

세 게시물 유형 모두 MVP 작성·조회·수정·삭제를 제공하며 공통 지역·주제·제목·본문·선택적 사진을 같은 게시물 시스템에 저장한다. 게시 완료 후 해당 상세로 이동하고 공개 목록·내가 만든 게시물에서 같은 원본을 조회한다. 지역 안건에는 별도 진행 상태가 없고 활동 입력을 표시하지 않는다. Figma의 참고 자료 링크·임시 저장/완료 표시와 지역 안건의 익명 선택을 FE 범위에 포함한다. Mock 저장과 실제 서버 보관을 구분하고 기관 사용자·활동 정보의 익명 금지는 유지한다.

지역 활동 정보는 출처·일정·장소·활동 상태를 필수 입력하고 외부 참여 링크는 선택 입력한다. 상태는 기본값 없이 예정·진행·종료·취소 중 하나를 필수 선택한다. 작성자가 네 상태 사이에서 자유롭게 직접 변경하며 시스템은 자동 변경하지 않는다. 종료/취소면 외부 참여 경로를 비활성화하고 예정/진행으로 되돌리면 재활성화할 수 있다. 문의 정보는 별도 이메일 입력 없이 작성자의 현재 등록 로그인 이메일을 사용하며 회원과 공유 링크 게스트에게 표시한다. 문의 정보가 없으면 `주최자 문의 정보를 확인할 수 없습니다.`를 표시하고 외부 링크의 유무/오류와 분리한다. 내부 신청·결제는 제공하지 않는다. 계정 이메일 변경/탈퇴 화면은 Privy 본인 확인으로 복구하며 실제 처리 시 활동 문의 이메일 갱신/제거를 연결한다. 실제 서버 처리 계약은 별도 확인한다.

투표는 독립 게시물이며 공통 항목·질문·선택지 2~10개·종료 일시·선택적 사진을 입력한다. 선택지 추가·수정·제거를 제공하되 최대 10개다. 진행 중/종료 상태와 실제 참여·결과를 제공한다. 진행 중 작성자는 제목·본문·사진·종료 일시를 수정할 수 있고 질문·선택지·지역·주제는 수정할 수 없다. 진행 중 투표는 작성자가 삭제할 수 있고 종료 후에는 수정·삭제할 수 없다. 참고 자료 링크 수정·종료 전 알림 선택/시점·종료 일시 변경 시 기존 예약 취소 및 새 시점 안내는 FE 범위다. 예약 보관·실행·발송은 BE API 미구현 / 실 API 연동 대기이며 투표 작성·참여는 실제 알림 발송 완료에 의존하지 않는다.

사진은 세 유형 모두 선택 사항이다. JPG·PNG 최대 10장, 게시물 전체 합산 최대 10MB이며 개별 파일당 10MB 기준이 아니다. 카메라/갤러리에서 첨부·미리보기·교체·제거하고 이동·선택 취소 시 공통 및 유형별 입력과 기존 사진을 유지한다. 사진이 없으면 목록·상세의 이미지 영역을 생략하고 기본/대체 이미지를 넣지 않는다. AI 이미지 생성은 비-MVP다.

[참여와 개인 활동]

공통 상세는 유형·주제·지역·제목·본문·작성자·사진·반응·댓글/답글·공유·북마크를 제공하며 해당 유형의 투표/활동 정보 및 현재 기관 채택 정보를 표시한다. 신고 진입·사유 입력·제출/Mock 접수·실패와 참고 자료 링크·허용 유형의 익명 표시는 FE 대상이다. 실제 신고 접수·심사/제재와 저장은 Backend 상태를 별도로 관리한다. 공감해요·필요해요·궁금해요는 각각 독립 등록·취소하며 세 개 모두 복수 선택할 수 있다. 반응 수는 세 반응 수의 합이고 투표 득표·댓글 수와 별도로 집계한다.

댓글/답글 작성·조회와 좋아요/싫어요 평가, 좋아요순/최신순 정렬은 MVP다. 평가는 상호배타적이며 반대 버튼은 전환, 같은 버튼은 취소한다. 좋아요순은 부모 댓글 좋아요 수 내림차순·동률 최신 작성 우선이고 최신순은 부모 작성 시각 내림차순이다. 답글은 원 부모 아래 1단계로 유지하며 기존 답글에 답해도 같은 부모 아래에 저장하고 대상 사용자명을 표시한다. 답글 좋아요 수를 부모 정렬에 합산하지 않는다. 회원·게스트 모두 동일한 사전 정의 문자열 포함 방식 금칙어 필터를 적용해 차단/수정 안내하거나 통과 시 즉시 게시한다. 실제 단어 목록은 임의로 결정하지 않고 AI 유해 문맥 판단·운영자 관리 UI는 제외한다.

투표는 선택 후 `투표 제출`로 저장한다. 종료 전 다른 선택을 제출하면 `선택을 변경하시겠습니까?` 확인 후 기존 표를 대체하고 취소하면 기존 표를 유지한다. 종료 후 신규 제출·변경을 제한한다. 선택지별 득표 수·득표율·전체 참여자 수를 공개하고 본인의 실제 선택은 로그인 본인에게만 표시한다. 다른 참여자의 이름·개인별/익명 식별자별 선택은 공개하지 않는다.

북마크는 상세의 동일 버튼 하나에서 로그인 상태를 판정한다. 회원은 등록/해제하고 저장 성공 시 `저장되었습니다` 팝업 후 현재 상세를 유지한다. 게스트는 저장 없이 로그인으로 이동하고 로그인/가입 완료 후 원 상세에 복귀한 다음 다시 버튼을 눌러야 저장한다. 마이페이지 목록은 유형·주제로 조회하고 상세로 연결한다. 목록 카드에는 등록/해제 버튼을 추가하지 않는다. 게시물 삭제 시 북마크 관계를 자동 해제하고 목록에서 제거한다.

MVP 마이페이지 메뉴는 프로필·나의 활동·내가 만든 게시물·참여한 게시물·참여한 투표·북마크·프로필 수정·이웃 인증·기관 인증이다. 활동 지역 변경은 프로필에서 제공한다. 관심 지역/키워드·알림/활동·설정·계정 정보 조회·로그아웃도 FE 진입을 제공한다. 이메일 변경/탈퇴도 FE에 복구하고 본인 확인은 Privy를 사용한다. 자체 비밀번호 흐름은 제외한다. 닉네임은 중복 없이 최대 10자, 한 줄 소개는 최대 50자이며 저장된 프로필 변경은 비익명 게시물 작성자 정보에 반영한다.

[기관 인증과 회원 기능 접근]

증빙 선택·첨부·신청 제출·접수·실제 인증 처리는 이번 MVP에서 제외한다. 별도 시연용 계정의 완료 지역을 서버에 준비하고 상태 조회·최대 3지역·해당 지역 참여 자격은 유지한다. 일반 가입·Privy 로그인·활동 지역 설정·기관 자격만으로 이웃 자격을 부여하지 않는다. 계정 준비는 #75, 조회 계약은 #74/#11을 따른다.

기관 증빙 입력·첨부·자료 제출·접수·실제 심사는 이번 MVP에서 제외한다. 별도 시연용 계정의 기관 정본·담당 지역·유효기간/완료 상태를 준비하고 현재 유효 상태 기반 역할·배지·업무 권한은 유지한다. 기관 자격이 주민 참여의 이웃 자격을 대신하지 않는다. 계정 준비는 #75, 조회 계약은 #74/#12를 따른다.

접수/첨부만으로 인증을 완료하지 않는다. 실제 운영자 심사·승인/반려·보완 메일·백오피스는 비-MVP다. 해커톤 시연에서는 개발자가 이웃/기관 인증 완료 상태를 직접 설정할 수 있다. 완료 상태·완료 지역/담당 지역을 실제 권한 판정에 연결하고 파란 배지를 별도 플래그로 주지 않는다. 기관 역할·배지는 현재 유효한 기관 인증 완료 상태에서만 파생하며 이웃/이메일 인증으로 부여하지 않는다. 기관 인증의 1년 유효기간과 만료 시 권한/배지 제거 정책을 유지한다. 증빙 보관/삭제 운영은 후순위다. 기관은 실제 민원 업무 담당자만 의미하며 단순 소속 학생/직원은 대상이 아니다.

기관 인증 완료 사용자는 전체 공개 지역 안건과 주민 의견을 열람한다. 담당자 목록은 제목·지역·반응 수·댓글/의견 수·게시 시각과 지역 필터를 제공하고 반응 수 내림차순으로 정렬한다. 담당 지역은 열람 범위를 제한하지 않고 채택 권한만 제한한다. 담당 지역 공개 지역 안건을 채택해 기관↔안건 별도 관계에 채택 사용자·시각을 저장한다. 게시물 상태를 바꾸지 않으며 기관별 독립 채택/취소를 허용한다. 취소 이력은 내부 보존하고 현재 유효 관계만 기존 담당자 화면의 `채택한 게시물` 필터/구역과 일반 상세에 표시한다. 일반 공개 정보는 기관명·채택 시각이고 담당자 개인정보는 비공개다. 채택 알림 없이 저장·조회할 수 있으며 MVP는 채택까지로 검토 중/처리 중/완료·실제 해결·행정 시스템 연동은 제외한다.

[기능 간 데이터와 복귀]

게시물·첨부 사진·댓글/답글·반응·북마크·투표·기관 채택 관계와 개인 기록은 동일 원본을 참조한다. 기관 채택은 투표/활동 진행 상태와 분리한다. 상세에서 돌아갈 때 원래 지역·유형·주제 및 메인/지도/개인 목록 진입 맥락을 유지한다. 로그인/가입 중 returnTo를 유지하고 복귀만으로 반응·평가·투표·북마크를 자동 실행하지 않는다. 추천 카드와 알림/활동 목록도 동일한 게시물 상세·삭제 안내에 연결한다. Backend가 없어도 같은 Mock 원본으로 FE 이동 맥락을 검증한다.

[MVP 범위와 추가 정의]

기존 기능 ID를 유지하되 MVP 사용자 경험과 FE/BE 개발 상태를 분리한다. `포함`은 사용자 경험의 목표 범위이며 구현 완료를 뜻하지 않는다. `일부 포함`은 명시적 제품 제거 예외 또는 FE UI와 후순위 서버 기능이 공존함을 뜻한다. 세부 축은 각 기능과 Figma 전수 대조를 따른다. `정책만 유지`는 Figma에 없는 운영·확장 기능의 정책 기록이다.

주요 사용자 컨텍스트는 주민 회원, 공유 링크 게스트, 기관 인증 사용자(민원담당자)다. 기존 계정 역할 ID는 두 회원 역할을 유지하며 게스트를 새 계정 역할로 추가하지 않는다.

증빙 선택·첨부·신청 제출·접수·실제 인증 처리는 이번 MVP에서 제외한다. 별도 시연용 계정의 완료 지역을 서버에 준비하고 상태 조회·최대 3지역·해당 지역 참여 자격은 유지한다. 일반 가입·Privy 로그인·활동 지역 설정·기관 자격만으로 이웃 자격을 부여하지 않는다. 계정 준비는 #75, 조회 계약은 #74/#11을 따른다.

기관 증빙 입력·첨부·자료 제출·접수·실제 심사는 이번 MVP에서 제외한다. 별도 시연용 계정의 기관 정본·담당 지역·유효기간/완료 상태를 준비하고 현재 유효 상태 기반 역할·배지·업무 권한은 유지한다. 기관 자격이 주민 참여의 이웃 자격을 대신하지 않는다. 계정 준비는 #75, 조회 계약은 #74/#12를 따른다.

지역 참여는 해당 지역 이웃 인증 완료 회원에게만 허용한다. 공유 링크 게스트 댓글/답글만 예외다. 기관 채택에는 현재 유효한 기관 인증과 해당 담당 지역이 필요하다. 기관 인증만으로 주민 지역 참여 자격을 대체하지 않는다.

MVP 게시물·댓글·반응·투표·북마크·개인 기록·기관 채택은 같은 원본과 관계를 참조한다. AI 요약은 추천·관심 정보 없이 동작하고, 댓글·반응·투표·채택은 알림 생성·예약·전달 없이 정상 저장·조회한다. Figma의 버튼·메뉴·입력·상태는 FE 대상이며 서버가 없으면 Mock임을 구분해 흐름을 검증한다. 실제 API/예약/푸시 완료를 FE 표시만으로 주장하지 않는다.

[개인 참여 기록의 통합 조회]

내가 만든 게시물은 세 유형을 모두 포함하고 유형별 본인 원본 목록/상세로 연결한다. 추가 진행/종료 상태 필터는 제공하지 않되 투표 상태는 카드·상세에 표시한다. 참여한 게시물은 본인의 세 반응·댓글/답글·댓글/답글 좋아요/싫어요·투표 참여를 게시물별 하나의 카드로 모은다. 댓글/답글 작성은 `댓글 작성`, 댓글/답글 평가는 `댓글 좋아요·싫어요`로 묶고 현재 유효한 모든 행동을 표시한다. 취소된 행동만 갱신하고 다른 행동이 남으면 카드를 유지한다. 북마크만 한 게시물·다른 사용자가 내 글에 한 행동은 제외한다. 전체·지역 안건·지역 활동 정보·투표 유형 필터를 사용하고 빈 목록은 `아직 참여한 게시물이 없습니다` 및 게시판 CTA를 제공한다.

참여한 투표는 별도 페이지의 전체·진행 중·종료 구분과 본인 실제 선택·현재/최종 결과를 제공한다. 최다 득표를 본인 선택으로 추정하지 않는다. 투표가 삭제되거나 접근 불가해도 개인 참여 기록은 유지하되 상세에서 접근 불가를 안내하고 삭제 본문·선택지를 재노출하지 않는다. 종료 전 알림의 입력·연결·표시 UI는 Figma에 존재하는 범위에서 FE 대상이며 실제 예약/발송은 BE API 미구현 / 실 API 연동 대기다.

나의 활동은 게시물 수와 다른 실제 행동 횟수다. 게시물 작성·북마크 등록·공감해요·필요해요·궁금해요 등록·댓글 작성·답글 작성·댓글 좋아요·댓글 싫어요·답글 좋아요·답글 싫어요·투표 참여를 각각 1회로 센다. 조회·수정/삭제·설정 변경·반응/평가 취소·좋아요↔싫어요 직접 전환·투표 선택 변경은 +0이다. 취소 후 동일 행동 재등록은 +1이고 북마크 해제 후 재등록도 +1이다. 투표 선택 변경은 기존 참여 1회를 유지한다. 개인 목록·활동 횟수는 원본 행동 기록을 참조하고 알림 목록도 별도 FE 경험으로 제공한다. 알림 생성/푸시 완료를 개인 기록 제공의 전제조건으로 삼지 않는다.

### 기능 영역 간 연결 원칙

- 게시물 원본은 목록·상세·지도·개인 기록·기관 담당자 목록이 함께 참조한다. 기관 채택은 게시물 상태가 아니라 기관과 지역 안건 사이의 별도 관계다.
- 이웃 인증 완료 지역은 게시물 작성과 주민 참여의 공통 전제이며, 기관 인증은 담당자 안건 열람·채택 권한만 추가한다. 두 인증은 서로 대체하지 않는다.
- 공유 링크 게스트 흐름은 동일한 공개 게시물 상세를 사용하되, 댓글/답글만 예외적으로 허용한다. 회원 전용 행동은 로그인 후 원 상세 복귀까지만 연결하고 자동 실행하지 않는다.
- AI 요약, 지도 대표 게시물, 개인 활동 기록은 게시물 사본을 만들지 않고 각각 게시물 원본과 참여 관계를 읽어 표시한다.

추천·관심 정보·알림·신고·설정·작성 보조의 FE 화면도 같은 제품 Domain에 포함한다. 서버 이벤트 생성·예약/푸시·운영자 심사는 독립된 Backend 후순위이며 FE 작업의 선행조건이 아니다.

## 차별점

MVP는 지역 안건·지역 활동 정보·투표를 같은 게시물 시스템으로 제공하고 공유 링크·게스트 댓글로 첫 참여의 진입을 줄인다. 지역 기반 탐색·공개 원문 AI 요약·댓글/답글·반응·실제 투표·개인 기록으로 이해와 참여를 연결한다. 기관 담당자는 전체 공개 안건과 주민 의견을 읽고 담당 지역 안건을 채택하며 주민은 현재 채택 기관명·시각을 확인한다. 채택은 별도 관계이고 실제 민원 해결을 보장하지 않는다. 추천·알림·활동·설정 화면의 FE 경험도 MVP 검증에 포함하되 Mock 사용자 흐름 검증과 실 API 기반 효과 검증을 구분한다.

## 대상 사용자

지역 주민 모두가 사용할 수 있지만, 핵심 사용자로는 참여 창구에 대한 정보가 없거나 시간이 없어서 지역 문제에 잘 참여하지 못하는 사람들을 보고 있다.

## 핵심 지표

기존에 지역 문제에 잘 참여하지 않던 사람들의 서비스 활동(게시물 게시, 댓글 남기기, 반응 남기기, 공유하기 등)의 빈도를 30% 증가시킨다.

## 리스크 및 검증 제한

채택된 게시물이 기관 인증 사용자(민원담당자)에게 전달되더라도 지역 고위 인사에게 이어질지는 불확실해 실제 해결에 도달하기 어려울 수 있다.

링크 공유와 게스트 참여로 초기 접근성을 높여도 이후의 지속적인 사용을 이끌 수 있을지는 미지수이다.

[와이어프레임 미리보기 제한과 미완료 검증]

현재 Manyfast 와이어프레임 미리보기에서 로그인 상태에 따른 북마크 조건 분기와 returnTo 복귀 경로 전달·복원을 실행하는 형식은 확인되지 않았다. 미리보기의 북마크 버튼은 저장 완료 팝업으로, 로그인 버튼은 메인 이동으로 고정되어 있다. 유저플로우의 ‘미리보기 제한/미지원’, ‘팝업 고정’, ‘메인 고정’ 표시는 이 도구 제한을 뜻한다.

서비스 요구사항은 유지한다. 동일한 북마크 버튼 클릭 후 회원은 저장·완료 팝업·현재 상세 유지를 수행하고, 게스트는 저장 없이 로그인으로 이동해야 한다. 로그인 성공 시 복귀 경로가 있으면 원래 게시물로, 없으면 기존 메인으로 이동해야 한다. 로그인 복귀 직후 자동 저장하지 않고 동일한 버튼을 다시 클릭했을 때 저장해야 한다. 미리보기의 고정 동작을 게스트 저장 허용이나 모든 로그인 후 메인 이동 정책으로 해석하지 않는다.

미리보기 팝업과 화면 이동만으로 실제 데이터 저장·권한 검증·로그인 상태 분기·게시물 복귀가 구현되거나 검증되었다고 판단하지 않는다. 이 동작은 실제 구현 시 검증할 미완료 항목으로 남긴다.

## 범위 대조 및 확인 필요 (2026-10-07)

- PRD와 기능명세서의 **A~AH 사용자 경험 범위**, 복구/제품 제거 예외 목록을 동일하게 대조했다. Figma 존재 화면은 FE 대상이며 BE 개발 상태는 독립이다.
- 지역 참여는 이웃 완료 지역, 기관 채택은 현재 유효한 기관 자격·담당 지역을 사용한다. 게스트 공유 상세 댓글/답글만 예외다. Privy 인증·활동 지역·기관 자격만으로 이웃 참여 자격을 부여하지 않는다.
- 북마크만 한 글은 참여한 게시물에서 제외하고 등록 활동 +1을 유지한다. 로그인/가입 복귀만으로 원 행동을 실행하지 않는다. 기관 채택은 기관↔지역 안건 관계이며 후속 민원 상태를 추가하지 않는다.
- BE 개발 후순위는 FE 화면 제외 사유가 아니다. 추천·알림·신고·설정·작성 보조 UI는 Mock/Contract 검증을 선행하고 실제 데이터 저장·조회·예약·발송은 별도 Integration으로 확인한다.
- 확인 필요: 기능별 Request/Response·오류·인증 권한 계약, Privy/로컬 회원·로그아웃 연결, 파일 업로드/삭제·24시간 정리 계약, Gemini 실제 모델/생성 계약, 실제 금칙어 목록. 새로운 endpoint·DB schema·서버 정책을 이 문서에서 확정하지 않는다.
- 기존 후순위 운영 세부(증빙 종류·심사/보완 메일·보관/삭제·신고 제재 기준)는 그대로 확인 필요다. 계정 이메일 변경/탈퇴 FE는 복구하며 Privy의 본인 확인·지원 방식과 로컬 회원 동기화·탈퇴/세션 계약은 별도로 확인한다.
- API SPEC의 `비-MVP / 후순위`는 해당 API·서버 업무의 구현 범위와 우선순위로 해석하며, Frontend 화면·입력·상태·Mock 사용자 흐름의 제외를 뜻하지 않는다. 통합지침서·FE 상세지침서·협업문서와 GitHub 작업 범위는 최신 제품·FE 복구 기준을 적용하고, API 범위 표기를 FE 제외로 전파하지 않는다. FE 복구를 이유로 API SPEC을 변경하거나 Backend 구현 범위를 확대하지 않으며 미준비 API는 실 API Integration 대기로 별도 관리한다.
