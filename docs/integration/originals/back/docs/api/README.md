# API 계약 문서

2026-10-07 현재 서비스 선택·MVP 변경은 [결정 변경 기록](../specs/Discushion_MVP_결정변경_2026-10-07.md)과 각 기준 문서의 같은 날짜 반영을 확인하세요. 계약/문서 후속은 #74, 시연용 계정 준비는 #75입니다. 기존 비밀번호/증빙 신청 예시는 현재 MVP 계약이 아닙니다. API 내부 버전은 v1.1.2이며 변경된 경로/DTO는 합의 대기입니다.

현재 저장소에는 [Discushion API 명세](./Discushion_API_SPEC_v2.md)가 있다. 파일명은 API_SPEC_v2이며 내부 버전은 v1.1.2다. 기존 #2 검토 자료에 #74 사용자 결정의 영향·변경 전 계약 이력을 구분해 반영한 기술 계약 초안으로, 실제 구현이나 FE/BE 합의 완료를 뜻하지 않는다.

[#2 공통 API 계약 검토표](./Discushion_API_CONTRACT_검토표_2026-10-07.md)는 기존 경로·DTO안을 유지하면서 공통 규칙, 미정 사항, 결정 역할과 관련 구현 이슈를 정리한다. 검토표의 제안과 팀이 실제 합의한 사항을 구분한다.

동일 Part의 FE/BE 담당자가 구현 전에 실제 명세를 기준으로 아래를 합의하고 작업 카드에 연결한다.

| 항목 | 기록할 내용 |
| --- | --- |
| Method / Endpoint | 실제 메서드·경로 |
| Request | path/query/body, 필수·선택, 형식·제약 |
| Response | 필드·타입·nullable·목록·집계 형식 |
| Status Code / Error | 정상·오류 상태 코드, 오류 코드·메시지·응답 구조 |
| 인증·권한 | 회원·게스트 접근, 이웃 인증 완료 지역, 유효 기관 인증·담당 지역 등 |
| 변경 이력 | 관련 기능 ID, 담당자, 변경 전후, commit SHA, 적용 순서·상대 담당자 확인 |

계약 합의 → 각 Part 구현·검증 → 실제 연동 확인 → back/develop 대상 PR·리뷰 순서로 진행한다. #2 작업 브랜치는 back/feature/2-contract이며 develop/main에 직접 push하지 않는다. mock만 확인한 결과는 실제 연동 완료로 기록하지 않는다.
